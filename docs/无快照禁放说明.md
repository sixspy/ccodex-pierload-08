# 无快照禁放说明（裁决 · 当日锁死）

案号：快照案辛 · 第 8 号
日期：2026-11-24
适用系统：港口过磅闸口（pierload）
正式行：PL-H08

## 一、案情

放行册已写入正式行 PL-H08，但闸代快照（gate_seals）缺失该票最新闸代；
对账页仍把该票标记为「已放行齐套」。即：无最新快照，正式册却出了正式放行。

## 二、正确性口径（就闸口，两边不得混用）

放行成立的唯一口径以**闸口**为准：一票被正式放行，当且仅当
`gate_seals` 中存在该票**最新闸代**（`ticket_generation = weigh_tickets.generation`）
的已封闸快照。

- 提单册（reconcile / proof）只允许引用闸口事实，不得自行把票标成「已放行齐套」。
- 任何页面（放行页、快照页、对账页、过磅页、总览页）展示的放行/齐套状态，
  必须同源来自闸口库表，禁止各页私算口径。

## 三、路径裁决

候选两条，互斥，不得混用；第三路（混合）禁止——混用会让无快照仍出正式放行。

- **甲路径（裁决采用）**：最新闸代快照缺失时，放行整笔回滚，正式册零增。
  放行接口在同一事务内先校验最新闸代快照存在；缺失即拒（HTTP 409），
  `gate_releases` 零插入、`weigh_tickets` 状态零改动。
- 乙路径（不采用）：放行先写影子意图，待快照齐套后原子晋升，正式零改。
  当前库表无影子意图/晋升设施；若半引入即构成甲乙混用，正是本案缺陷形态，故拒绝。

**裁决：采用甲路径。当日锁死。**

## 四、偏航处置

任何偏离本裁决的改动，记「无快照禁放偏航」并拒写：

1. 只改对账页勾选样式、不改闸口写入规则 —— 偏航，拒写。
2. 引入影子意图/待晋升态却无原子晋升闭环 —— 甲乙混用，偏航，拒写。
3. 放行先落正式行、事后再补快照 —— 偏航，拒写。
4. 对账页把影子/未齐套状态误记为「已放行齐套」—— 偏航，拒写。

## 五、并发裁决

双会话同票同时抢放行，须占同一把闸口锁（`gate:{ticket_id}`）。
封闸（写快照）与放行对同一票统一使用该闸口锁键，杜绝「快照写一半放行插进来」的跨服务窗口；
后到会话只在 `contention_log` 记争用痕，不写任何放行/快照业务数据，返回 409。
超重开/闭环针对「旁路挂起」票，而挂起态既禁封闸也禁放行，业务态上与闸口两写天然互斥，不并锁。

## 六、红测链（不得省略，先红后绿）

1. 失败测甲：无最新闸代快照却放行 → 必须 409 且正式册零增（当前实现放行成功，红）。
2. 失败测乙：对账/单票证明不得把无快照票记为已放行齐套（当前口径错误，红）。
3. 争用失败测：双会话同票抢放行，后到只记争用痕、不写放行（当前锁键不互斥，红）。

三红确认后，方准改封闸服务、放行服务、对账服务、过磅服务，并改放行页与快照页；
五页（放行、快照、对账、过磅、总览）同源核对。收工三绿。
